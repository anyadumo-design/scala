# Як тема потрапляє на сайт

Так само, як на Vil'nyi: код живе в GitHub, туди робиться push — і зміни
самі їдуть на сервер. В адмінку заходити не треба.

Різниця одна: на Vil'nyi сервер віддає SSH, тож там конвеєр ще й чистить
кеш командою на сервері. На цьому хостингу SSH для акаунта не ввімкнений,
тому їдемо по FTP. На заливання теми це не впливає.

## Що треба зробити один раз

У GitHub: репозиторій `anyadumo-design/scala` → **Settings** → **Secrets
and variables** → **Actions** → **New repository secret**. Чотири штуки:

| Ім'я | Що вписати |
|---|---|
| `FTP_HOST` | адреса FTP-сервера з DirectAdmin |
| `FTP_USER` | логін FTP-акаунта |
| `FTP_PASSWORD` | його пароль |
| `FTP_PATH` | шлях до теми на сервері |

`FTP_PATH` — це зазвичай
`/domains/scalahome.com.ua/public_html/wp-content/themes/scala-atelier/`,
але точний шлях видно у файловому менеджері DirectAdmin.

Хост, логін і пароль беруться в DirectAdmin: **Керування акаунтом →
Керування FTP**. Там же створюється новий FTP-акаунт, якщо потрібен
окремий під деплой — так навіть краще: його можна відкликати, не чіпаючи
основний.

Паролі вставляються **в GitHub**, не в листування. Після збереження їх
не видно навіть власнику репозиторію — тільки роботу під час заливання.

## Далі

`git push` у `main` — і за хвилину тема на сервері. Конвеєр перед
заливанням перевіряє синтаксис усіх PHP-файлів: якщо десь помилка,
нічого не поїде.

Запустити вручну можна з вкладки **Actions** → **Deploy theme** →
**Run workflow**.

## Чого конвеєр не робить

Не активує тему. Активація — одноразова дія, і без SSH зробити її
звідси нічим: один клік в адмінці, один раз за життя сайту.
